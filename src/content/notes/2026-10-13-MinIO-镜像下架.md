# MinIO 官方镜像下架，docker compose 拉不到镜像

## 卡在哪

执行 `docker compose up -d` 失败，报错：

```
pull access denied for minio/minio, repository does not exist or may require 'docker login'
```

同时 postgres、redis 显示 `Interrupted`。

![](/media/notes/8a182850f9.webp)

## 我怎么定位的

1. **对比前后两次报错**
	- 第一次：`failed to connect to the docker API`，daemon 没启动
	- 第二次：`Error response from daemon`，说明 daemon 已经在回应
	- → 划掉「daemon 没准备好」的假设

	![](/media/notes/ac11c1d1a5.webp)

2. **区分颜色**
	- `Interrupted`：被并行拉取的失败连带取消的
	- `Error`：才是根因
3. **对照实验**
	- 单独 `docker pull redis:7-alpine` → 成功
	- 单独 `docker pull minio/minio:latest` → 失败
	- → 范围缩小到 minio 镜像本身

	![](/media/notes/7ae3edcc83.webp)
	![](/media/notes/421e7ba0f6.webp)

4. **去一手来源**：报错「不存在或需要登录」本身分不清
	- Docker Hub 页面 → 404（对照：redis 的正常页面）

	![](/media/notes/374976250c.webp)
	![](/media/notes/0b3d4a56b0.webp)

	- GitHub 仓库 → 标注 NO LONGER MAINTAINED，并于 2026-04-25 归档

	![](/media/notes/9f162898e3.webp)

## 根因 & 修复

> **根因**
> MinIO 官方停止维护并下架了 Docker Hub 镜像，教程写于下架之前。

**修复思路**：把配置拆成两类，保留前者，按 RustFS 文档重写后者。

| 对外约定（保留） | 镜像内部细节（重写） |
|---|---|
| 宿主机端口 7313 / 7314 | 镜像名 |
| 账号密码的值 | 启动参数 |
| 数据卷名 | 变量名 |
| | 健康检查命令 |

最终换成 `rustfs/rustfs:1.0.1`，后端代码和 `.env` 不用改。

## 下次我会先做什么

> **> 镜像拉不下来，无非两个原因：镜像不存在，或者需要登录后才能拉。顺着这两个思路去排查。**
