### 怎么用？

首先来安装 skill，直接将下面这段话发给 Codex 即可（其他的 AI Agent 也是可以的，比如 Claude Code）：

```
帮我安装 guizang-ppt-skill。请把 https://github.com/op7418/guizang-ppt-skill 克隆到 ~/.claude/skills/guizang-ppt-skill,安装完成后检查 SKILL.md、assets/、references/ 是否存在。
```

如果之前已经安装过了这个 skill，要更新的话，就发下面这段话：

```
帮我更新 guizang-ppt-skill。请进入 ~/.claude/skills/guizang-ppt-skill 执行 git pull,然后告诉我当前最新 commit。
```

在安装完毕之后，只需要说一句 "请调用 guizang-ppt-skill 来帮助我做一篇 PPT"，然后 Codex 就会主动的问你一些问题：

1. 选择风格

有两种风格可以选择：

- 电子杂志风 × 电子水墨

像 _Monocle_ 贴上了代码,适合叙事、观点、分享、个人风格表达

- 瑞士国际主义

网格至上、单一高饱和锚点色、直角、发丝线、极致字号对比,适合事实、产品、分析、方法论表达

2. PPT 的主题 & 受众 & 场景

如果你有现成的稿子是最好的了，Codex 可以直接把它提炼成适合 × 风格网页 PPT 的叙事结构、页数分配和重点文案

任一种形式的稿子都是可以的：

- 发链接
- 直接粘贴正文
- 给我本地文件路径
- 只发你最想讲的那几段也可以

如果没有的话，简单回答 "PPT 的主题 & 受众 & 场景" 这三个问题即可，如果自己也不是很清楚的话，那就让 Codex 引导即可

3. 分享时长多久？
 
 歸藏老师提供的参考是：
 
 15 分钟 ≈ 10 页，30 分钟 ≈ 20 页

当然这个是因人而异的了，如果没有特别要求的话，就是在 7-9 页

4. 有没有原始素材？

比如草稿，文章链接，之类的，只要是相关的内容都可以提供给 Codex

5. 图片

如果你是有图片的，那么需要将图片放到 ~ppt/images 文件夹当中即可，为了后面 Codex 可以更好的实现是需要对图片进行如下规则的重命名的，规则如下：

```
└── images/     
    ├── 01-cover.jpg     
    ├── 03-figma.png     
    └── 05-dashboard.png
```

- 页号补零 + 英文语义——01 不是 1，cover 不是 fengmian。方便按顺序排，AI 引用也清晰

- 照片用 JPG，截图用 PNG——截图带文字，PNG 保真不糊

- 单张 ≥ 1600px 宽——大屏投影才不糊

我知道会觉得要自己重命名实在是太麻烦了，没关系，重命名这件事情完全是可以交给 Codex 来做的，我们只需要负责将图片放到对应的文件夹当中即可

6. 硬约束

如果有什么内容是一定要出现的，或者 ×× 一定不能出现，也需要和 Codex 说清楚

上面的几个问题，是回答完一个才会继续问下一个的，所以不需要有一次性回答完所有问题的压力

在回答完上述的问题之后，就会生成一份大纲和主题节奏表来方便我们对齐需求，如果有需求不对的地方，在这里及时修改就好，不建议没对齐需求就开始，因为这样后面是高概率会返工的

### 其他功能：

1. 让 GPT-Image 2.0 出图

这个是藏老师最近更新的功能，如果是在Codex 环境里用，PPT 写完它会主动问你："要不要给这份 PPT 生成几张配图？"

如果你需要他会自动帮你按照所选的 PPT 风格和内容生成合适类型配图

生成图会自动适配你当前 deck 的风格和主题色，整个 deck 的一致性是不需要担心的

2. 制作平台封面

也是最近新更新的功能之一，比如：

- 小红书 3:4
- 公众号头图 21:9

直接这样和 Codex 说即可：

```
基于这份 PPT 的核心观点，给我一张 3:4 的小红书封面。
```

```
基于这份 PPT 的核心观点，给我一张 21:9 的公众号头图。
```

生成的封面的一致性也是会保证的

### 一些注意点

1. 最后生成的是 HTML

最后生成的是 HTML，并不是 ppt，也无法导出成 PPT 进行编辑，如果需要对内容进行修改的话，直接和 Codex 沟通就可以了

现在很多都是 HTML 都是当做 PPT 使用了，一样有翻页的效果，动效和色彩什么的都很好

2. commit 提交

正常来说，在生成完毕设计稿之后是会按照流程提交 commit 的，也是存档到 GitHub 仓库当中，主要影响的是版本管理，而不是做 PPT 本身

好处是后面如果我们继续做 PPT，实现过程中改了结构、文案或图片策略，都能很清楚地知道：

- 最初确认过的设计稿是什么
- 后面改了哪些东西
- 如果改坏了，怎么回退

所以如果你是偶尔会用到这个 skill 的话，创建的必要性不是很大；但如果会经常使用的，那么我是很建议专门为其创建一个 GitHub 仓库的
