### 1. Free-domain

项目名：Free-domain

GitHub 仓库地址： https://github.com/DigitalPlatDev/FreeDomain

想搭网站但不想花几十上百块买域名，或者被免费子域名的限制搞得头疼（比如不能绑定自定义 DNS）

**这个项目直接送你一个可以自由配置的二级域名，绑定自己的服务器或托管服务，帮你省下域名钱**

这个项目有 173k 的 Star，可见大家对于省钱这件事情是认真的

但在这里我需要说几个点：

1. 域名后缀

这个网站确实可以可以提供免费的域名，但是后缀并非传统意义上的主流域名，**比如 `.com`、`.cn` 这些都是没有的**，那么它支持哪些后缀呢？下面我给大家列了一张表

![](/media/articles/github-w22/c2df5bfdda.webp)

这些后缀基本都没有见过吧，至少萍雨在此之前是没有见过的，看起来不是很正规的样子，但确实是可以正常使用的域名后缀

因为这些后缀看起来不是很正规嘛，所以不是很推荐大家用这些后缀作为自己简历 / 作品集等正式网站的域名，**对于这些网站，更加推荐大家买  `.com`、`.cn` 这种主流域名后缀**

那么什么情况下，可以使用这个网站提供的域名后缀呢？大概是如下的这些场景，可以来薅一下羊毛

- 测试项目
- 临时 demo
- 个人小工具
- 不太在意品牌感的开源项目预览
- 学习 DNS / Cloudflare / 部署流程

2. 可以薅多少个免费域名？

**作为新用户的普通账号，是只能获得一个免费域名的**

官方提供了两种免费提高额度的方法：

第一种是典型的邀请制，邀请朋友注册成功之后，双方都可以获得 +1 个域名配额，比如这是我的邀请链接

https://dash.domain.digitalplat.org/signup?ref=aphbAuAwjl

大家如果想要薅羊毛的话，可以从萍雨的链接注册，非常感谢！

第二种方法就是创作者计划，这个就不展开了，因为用这种方式的毕竟是少数中的少数

**不过请注意：不建议多开账号绕限制。平台注册页和说明都写了每个个人或组织限制一个账户，这种做法可能导致账号或域名被暂停**

### 2. awesome-architecture

项目名：awesome-architecture

GitHub 仓库地址： https://github.com/study8677/awesome-architecture

如果你也是一位码农，看着 AI 编程的快速发展难免会新生焦虑，**你写代码很溜，但 AI 比你更溜**

这个项目说了一个扎心的事实：未来会写代码的编码能力不值钱了，会想架构才值钱

很多人写了很多年代码，依然画不出自己系统的架构图，也说不清「为什么用这个而不是那个」

**原因是：学校和教程几乎都在教「实现」，很少有人系统地教「判断」**

- 实现能力回答的是：这个功能怎么写出来？
- 架构判断回答的是：这个系统应该长什么样？哪里会出问题？我在拿什么换什么?

这套教程，专门补「判断」这一课。不教你任何一门语言、任何一个框架。 它教你一种可迁移、不会过时的能力：在写代码之前，先把系统想清楚

---

这套教程分为两个部分——系统化教程 & 架构模板库

前半部分用 26 章教程建立架构判断力，后半部分用 25 个真实系统模板帮你快速理解不同类型系统该怎么设计、会在哪里出问题、如何演进

**其中后半部分除了电商平台、支付系统等经典架构模板；也有很火的 Claude Code、Codex、OpenClaw（龙虾）、Hermes（爱马仕）的架构分析**

### 3. adhd

项目名：adhd

GitHub 仓库地址： https://github.com/UditAkhourii/adhd

你是否也遇到过这种情况，在让 AI 进行头脑风暴的时候，AI 输出的内容要要么不切实际，要么是你知道的，要么过于普通，不能给你 "啊哈" 的感觉

那么这个仓库就是给 AI agent 用的头脑风暴 skill

**它会让 AI 从多个隔离视角并行发散**，要求用多个独立 agent / branch 分别思考，每个分支看不到其他分支的答案，从而让多个上下文分别从不同认知框架出发，减少互相锚定，比如：

- 监管者视角：什么必须可追踪、可拒绝、可审计？
- 竞争对手攻击视角：这个产品哪里会被打穿？
- $0 预算 1 小时视角：最粗糙但能验证的版本是什么？
- 无限预算 10 年视角：终局形态是什么？
- 3am on-call 视角：上线后什么会把你叫醒？

这些 frame 会逼模型离开常规产品经理模板

然后再统一评分、聚类、排雷和深化，最后输出

上面的那些大家应该没看懂，但没有关系，**只需要记得如果你之后有遇到类似头脑风暴、开放式方案选择、产品切法、命名、定位、架构取舍、模糊问题排查，就可以优先考虑用这个 adhd skill 即可**

相信它大概率会让你啊哈的

### 4. gitignore

项目名：gitignore

GitHub 仓库地址： https://github.com/github/gitignore

如果你用 Git，那么你几乎一定会接触到 `.gitignore` 文件

毕竟如果没有 `.gitignore` 文件的话，直接把一堆编译文件、缓存、配置文件也跟着存档到仓库当中，直接就污染仓库的内容，当然更为重要是容易把有敏感信息的内容也一并存档到仓库当中，比如 API Key

所以无论你是 Git 新手，亦或者是老司机都会需要一个 "忽略文件" 的模板合集，帮助你一键稿定哪些文件不该提交

它是 GitHub 上最古老、最知名的开源项目之一，Star 数高达 17 万。无论你用什么语言或工具，都能在这里找到现成的忽略规则，省去自己查文档、试错的时间

### 5.  pianke

项目名：pianke

GitHub 仓库地址： https://github.com/zhaoyue4810/pianke

照例推荐一个偏娱乐的小仓库作为结尾哈~

如果你是一名摄影爱好者或者是从事摄影相关行业的朋友，多多少少会有那种一个场景拍了很多照片，但在筛选时，看着十几张甚至几十张相似照片感觉到头大的经历

这个仓库就是来帮助你一定程度上解决这件问题的

**它的价值点在于可以先帮助你进行一波初筛、分组、最后用户有绝对的去留权**

在初筛的阶段，会帮助你筛选出 "主体不够清晰"、"主体失焦"、"画面过曝" 等问题的图片，在筛选之后会标注好原因方便你进行最后的判断来加快筛选废片的过程

**不过请注意，它的 "模糊、曝光、主体、相似度" 等判断逻辑主要来自摄影场景，因此面对 AI 生成封面、PPT 截图、公众号头图、设计海报时，可能会把 "设计上的留白、柔光、高亮、景深、低对比" 误判成摄影废片**

还有一点就是，只能在 PC 端使用
