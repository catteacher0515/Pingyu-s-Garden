### 1. wechat-cli

项目名：wechat-cli

GitHub 仓库地址： https://github.com/huohuoer/wechat-cli

**特别注意：该 GitHub 仓库并非腾讯官方出品的**

这个仓库可以帮助你实现如下的功能：

| 功能模块  | 作用              |
| ----- | --------------- |
| 最近会话  | 查看最近聊天列表        |
| 聊天记录  | 查看指定聊天历史        |
| 全局搜索  | 搜索关键词           |
| 联系人查询 | 搜索联系人详情         |
| 群成员   | 查看群成员           |
| 聊天统计  | 消息统计分析          |
| 聊天导出  | 导出 Markdown/txt |
| 微信收藏  | 查看收藏内容          |
| 未读消息  | 查看未读会话          |
| 增量消息  | 获取新增消息          |
| 初始化   | 提取数据库密钥         |

其中我个人会用到的功能是导出聊天记录，因为我有一些零碎的想法是写在微信里的，需要把这些想法给摘出来；全局搜索也会是一个比较好用的功能

对于做知识付费的小伙伴来说，群聊相关的功能应该会适合一些

还有一个小点的补充，对于数据的导出，不只是支持文本聊天的

文本、图片、视频、表情、文件等等都是支持的

而且还支持按照时间范围进行过滤，在使用的时候记得时间范围稍微小一些，因为如果时间跨度太大的话，导出的内容一般就更多，等待的时间就太长，如果中间出现一些网络波动等异常情况就。。。

---

从上面支持的功能当中可以看出，是支持 "读取"、"搜索"、"导出"、"分析" 的功能，但并不支持 "发消息"、"自动回复"、"自动控制微信" 等功能

原因也很简单，开发者在主动的降低风控风险，因为所支持的功能的实现主要靠的是读取本地数据库，而不支持的功能就属于 "接管微信行为" 的范畴了，这两者完全就不是一个危险等级

无法否认这种仓库肯定还是有一定被微信警告或者封禁的风险的，但属于低风险，所以如果大家要尝试的话，可以先用自己的微信小号试一下

### 2. web-access

项目名：web-access

GitHub 仓库地址： https://github.com/eze-is/web-access

这是我最近最喜欢的仓库，基本上每次打开 Claude 或 Codex 第一条调用的 skill 就是这个

这个 skill 可以实现什么功能呢？简单来说，你通过 Chrome 可以访问什么内容，那么 AI Agent 通过这个 skill 就能够访问什么内容

现在多数的大模型都是支持联网功能的，但是即使是这样有很多内容依然是拿不到的，比如说公众号，B站上的内容，以及需要需要登录访问、付费访问的内容

通过这个 skill 基本都可以访问到，属于用了就离不开的那种，这次篇幅有限就不展开了，只需要记住下面这句话就可以了

你通过 Chrome 可以访问什么内容，那么 AI Agent 通过这个 skill 就能够访问什么内容

后面我大概率为单独写一篇文章来和大家分享一下我是如何使用这个 skill 的，真的夯爆了！

### 3. agency-agents

项目名：agency-agents

GitHub 仓库地址： https://github.com/msitarzewski/agency-agents

简单来说这个仓库就是 144 个系统提示词，但千万不要因此就轻视它，这个仓库在 GitHub 上有 105k 的 Star，简直恐怖如斯，能达到这个数量级，必然说明这些系统提示词不是一般的提示词

内容涵盖工程、产品、增长、运营等领域，下面我会以表格的形式呈现，这 144 个系统提示词肯定是不需要大家都会用到的，大家各取所需即可

比如我用的比较多的就是内容创作的部分，来帮助我更好的选题，打初稿，写适配于各个平台的标题，检测文章当中的敏感点等等（被限流实在是太痛了...）

### 4. superpowers

项目名：superpowers

GitHub 仓库地址： https://github.com/obra/superpowers

想象一下，你有一个超级聪明但有点莽撞的程序员助理，你一开口说要建个网站，他立刻就开始噼里啪啦敲代码，结果做出来的东西跟你想要的差了十万八千里

这个叫 "Superpowers" 的项目，就是为了解决这个头疼的问题，毕竟返工的痛，不言而喻

它不是教你写代码，而是教你的AI助手怎么做一个靠谱的 "人"，来完成需求对齐的工作，在需求对齐，输出一份完整 spec 文档之后在进入编码层面的实现

ps：spec 文件 = 描述 "应该怎么做" 的规则文件

它会先让你把需求说清楚，把大目标拆成小步骤，然后像项目经理一样，派好几个小助手各自干活，互相检查。如果你想让你的 AI Agent 从 "愣头青" 超级进化为 "老司机"

所以你如果也经历过因为需求没有对齐导致的返工问题，那么这个仓库会很适合你

### 5. mykonos-island-voxels

项目名：mykonos-island-voxels

GitHub 仓库地址： https://github.com/boona13/mykonos-island-voxels

最后来一个温馨的小玩具作为收尾哈~

你有没有想过，只用鼠标点一点，就能在浏览器里搭出一座圣托里尼风格的小岛？这个项目就是这样一个“数字乐高”——你从右侧的素材库里选中教堂、风车、橄榄树，然后往网格上轻轻一放，一座蓝白相间的米科诺斯小镇就慢慢长出来了

它没有任何目标、分数或资源限制，纯粹为了让你享受 "摆东西直到看着顺眼" 的治愈感。适合所有想在忙碌中放空几分钟的人——不需要下载任何东西，打开网页就能玩

有几点是需要注意的

1. 仓库当中所提供的在线访问的链接是无法访问的，需要大家在本地下载之后访问

2. 游戏里的场地大小是写死在配置里的 14 x 14，所以不能在游戏里直接扩大地图的尺寸，但可以通过在源码层面上进行修改，把 width 和 height 改大，比如 20 x 20、24 x 24；但也请注意：地图越大，首次加载和渲染会更重
   
3. 搭建好的小岛是可以保存的，可以通过 S 键手动保存，也可以通过左侧工具栏当中的 "Save"，下次重新打开同一个地址时，会自动读取上次存档，存档存在浏览器的 localStorage 里，不是服务器
   
   也就是说你正常关掉标签页、关掉 Chrome，再回来，一般还在；但前提是还是这个浏览器、这个地址 127.0.0.1:59286；如果清浏览器站点数据 / 无痕模式 / 换端口 / 换浏览器，可能就没了
