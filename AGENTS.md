## Content model

- Content collections in `src/content/`: `videos`, `notes`, `rants`, `posts` (category 教程 / 文章; includes the 13 restored Zhihu articles), `projects` (the three resume projects, all `wip: true`; old tools archived, no page). Schemas live in `src/content.config.ts`.
- `public/admin/config.yml` (Sveltia CMS) mirrors those schemas field by field. Change both together.
- `draft: true` entries show only in `npm run dev`.
- Full videos are not hosted here: they live on B站 etc. Video pages do not embed the B站 player (decided 2026-10-16: the outside player is capped at 360P and clicking the picture opens B站); the cover and each chapter open the B站 video in a new tab, chapters with `?t=<seconds>`. Self-hosting on Cloudflare R2 was offered and declined. Optional short silent `preview` clips are the only video files in the repo.
- Articles are read on-site: on 2026-10-15 the 13 Zhihu articles were imported in full from the user's Obsidian drafts (one, topic-hot-tracker, from the published Zhihu page because no draft exists), images in `public/media/articles/<slug>/`. `origin` holds the Zhihu URL and renders a small 「本文首发于知乎」 credit at the end; `external` (link out, no on-site page) is only for posts whose text is not on the site. The user found jumping to Zhihu jarring; do not reintroduce outbound article links. Those 13 are hand-managed files; new articles come from Obsidian (property `发成文章: true`) and are generated into `src/content/posts/obsidian/` (wiped and regenerated each sync, never hand-edit).
- `notes` (学习笔记) are generated by `scripts/sync-notes.mjs` from the user's Obsidian vault (iCloud `Obsidian/`, ~2200 notes mixing study notes with private meeting notes and todos). Only notes with property `publish: true` (→ notes) or `发成文章: true` (→ articles; not `article`, which one vault note already uses as a text property) are exported; content containing tokens, private keys or public IPv4 addresses is skipped and reported; never sync the whole vault and never write into the vault. `src/content/notes/` and `public/media/notes/` are wiped and regenerated on every run, so never hand-edit them and keep notes out of the CMS. Publishing is automatic: launchd job `com.huapingyu.garden-publish` (installed 2026-10-16 with the user's approval via `scripts/install-auto-publish.sh`) runs `scripts/auto-publish.sh` every 5 minutes in a dedicated clone at `~/Library/Application Support/pingyu-publisher/repo`, skips when nothing in the vault changed, commits and pushes, and shows a macOS notification. Manual fallback: double-click `发布笔记.command` (`scripts/publish-notes.sh`).
- `rants` (发发神经) are short untitled posts with date + optional mood emoji, written in the CMS; the homepage shows the latest 3, `/rants/` shows all. The CMS stores `date` as Beijing wall-clock time without an offset, so it parses as UTC: format rant times and `fmtDay` in UTC (never convert to Asia/Shanghai, that adds 8h).

## Rendering conventions

- 项目, 笔记 and 视频 appear in nav and on the homepage only when they have published content (`getSectionPresence()` in `src/lib/content.ts`); 文章 and 发发神经 are always present. Empty-state copy is written for visitors, never admin instructions.
- Images: `npm run build`/`dev` first run `scripts/optimize-images.mjs`, which writes WebP copies (max 1600px) of `public/media` into `public/_opt/` (gitignored). Old-site illustrations, doodles and Zhihu covers live in `archive/old-site-content/assets/` and are not deployed.
- New videos need only the B站 URL in the CMS: `.github/workflows/fill-videos.yml` runs `scripts/fill-videos.mjs` on pushes touching `src/content/videos/**`, fills empty fields from the B站 API, downloads the cover, renames the file to `<BV>.md`, and commits back. An entry is treated as filled once `slug` equals its BV id; entries with an empty title are hidden. Video entries imported from Bilibili carry `slug: "BV…"` so URLs keep the BV id's case. Covers are downloaded to `public/media/videos/`. Videos have `series` (工具上手 / AI 认知 / 日常, drives the list-page filter) and `chapters` (`{at, title}`, copied from the B站 分段章节 via `api.bilibili.com/x/player/v2` `view_points`). The video list page uses the same header + pill filter + 3-column card grid as /articles/.
- `public/favicon.svg`, `public/og.png` (share card), `src/pages/sitemap.xml.ts` and `public/robots.txt` are part of the A design; detail pages pass their cover as the share image. Reference images through `opt()` from `src/lib/img.ts`. Note images are converted to WebP by `sync-notes.mjs`.
- Load and scroll reveals are pure CSS (`.reveal`, `.reveal-scroll`, scroll-driven `animation-timeline: view()`, `fill-mode: backwards`) so content never depends on JS to become visible. GSAP is for interactive motion (SplitText hero name, hover peek cards on `.list`, search palette). Headless or background-tab screenshots freeze these animations; verify motion in a foreground tab.

## Purpose (decided 2026-10-13)

- The site serves the user's 2027 winter-break internship search first: target role is **Agent development** (not Java backend; AI app dev only secondarily). Visitors to optimise for are interviewers.
- Homepage: one section per full screen with CSS scroll-snap (`html { scroll-snap-type: y mandatory }`, each `.screen` is 100vh); never let two sections share a screen. Order: hero (prototype D in `docs/prototypes/hero/d-combo.html`: IP in the centre with a speech bubble, click cycles expressions; section entries orbit around it, hovering one swaps the IP pose and shows count + latest item in a floating card. Entries keep a fixed size and pose changes are debounced, because the earlier version jittered; no role label and no tagline in the hero, the user dislikes the "Agent" tag; clicking the IP plays a quiet Web Audio SFX per expression, with a mute toggle stored in localStorage `ip-sfx`) → 项目 → 笔记 (Obsidian notes only) → 文章 (always shown, pointing IP pose, empty-state line until the first article) → 视频 → 发发神经 (always shown, facepalm IP pose, latest 3 or an empty-state line) → 关注我 (waving IP pose + platform cards, same paper/white-card style as the other screens). 关注我 exists only on the homepage; other pages get a one-line footer (`src/components/Foot.astro`, © + ICP) and the nav 关注我 link goes to `/#follow`. Nav: 项目 / 笔记 / 文章 / 视频 / 发发神经 / 关注我.
- Notes (`/notes/`, from Obsidian) and published articles/tutorials (`/articles/`, the `posts` collection, CMS label 文章) are separate sections and must never be merged into one list. `/writing` and `/posts` redirect to them.
- No "looking for an internship" call-to-action anywhere: the user finds it embarrassing and will recruit via social posts that link here.
- Projects marked `wip: true` show as cards with a 开发中 badge and no detail page; only state facts the user has confirmed.
- The three resume projects: AI 超级智能体, AI 修图智能体, 实习时做的内容运营工作台 (新通教育). They live in `src/content/projects/` as `wip: true` until the user supplies real details; never invent results, metrics or responsibilities. `noteTopic` links Obsidian notes (same `topic`) to a project page.
- Do not put a resume PDF or phone number on the site; the user applies via recruiting platforms.

## IP identity

- Palette comes from the user's IP character (`/Users/huapingyu/IP 形象/`): cream `--paper #fbf7ee`, ink `#1c2140`, navy `#23357d`, night `#131c46` (code blocks, hover labels), gold `--hot #f2b22c` (dots, highlights, hover fills; not for body text).
- The cursor is the gold winged-cursor badge applied as a native CSS cursor (`public/brand/cursor-*.png`, hotspots 1 6 / hover 1 14), not a JS-drawn element: cursor extensions (the user runs Custom Cursor) override native cursors, and a DOM cursor would stack on top of theirs. Only the hover label (`.cur-label`) is a DOM element. The user insists the badge is the cursor on this site even with their Custom Cursor extension on, so `global.css` overrides the extension's `html[data-cursorstyle]` variables and adds `!important` cursor rules with a raised-specificity `html:not(#_badge)` selector. Favicon is the badge on navy. IP poses are exported to `public/brand/*.webp`; regenerate from the IP folder rather than editing them.
